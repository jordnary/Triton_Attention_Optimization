# 公开文件范围与发布方法

公开版本包含源码、依赖约束、方法说明、公开提示词、匿名化报告与精选图表。本地实验资产、身份材料及机器配置应与公开版本分开保存。

## 文件范围

| 类别 | 处理方式 |
| --- | --- |
| `attention/`、`PixArt-alpha/` 与入口脚本 | 纳入版本控制，保留第三方来源注释 |
| `README.md`、`data/*.md`、`doc/report.md` | 公开说明，使用相对路径与通用示例 |
| `data/test.txt`、`pic/` | 公开提示词与报告引用的精选图表 |
| 模型权重、`pretrained_models/`、`checkpoints/` | 仅本地保留，从上游重新获取 |
| `data/prompt_embeddings/`、`output/`、原始基准输出 | 仅本地保留，可由实验流程生成 |
| `doc/*.pdf`、报告中间文件、`local/` | 仅本地保留，避免旧版身份信息与导出元数据进入公开版本 |
| 虚拟环境、编译缓存、测试缓存、日志 | 忽略；确认没有运行中进程依赖后可另行清理 |
| `.env`、密钥、证书、本地数据库、编辑器设置 | 忽略；不应写入源码或公开文档 |

`.gitignore` 对已跟踪文件和旧提交不生效。改为仅本地保存时，应取消 Git 跟踪并保留磁盘副本；这仍不会清除历史内容。

## 发布当前快照

若既有历史包含身份信息、个人路径或不拟公开的实验资产，应使用已审查的当前快照建立独立公开仓库。不要直接推送旧分支、旧标签或使用 `--mirror`。

完成修改并提交后，可创建 `local/` 暂存目录，将当前受版本控制的内容导出：

```bash
git archive --format=zip --output=local/public-source.zip HEAD
```

归档不包含 `.git/`、未跟踪文件或仅本地保留的 PDF，但仍以当前提交内容为准，不能代替隐私审核。解压后在独立目录初始化公开仓库，并在首次提交前配置拟公开的提交姓名与邮箱；Git 提交元数据本身也是公开内容。不要复制原仓库的 `.git/`。

如确需保留历史，应先备份并单独规划清理，再审核所有待推送分支、标签与提交元数据。历史重写与远端更新不属于普通文档修改。

## 检查方法

以下命令用于本地核查，原始输出可能含敏感内容，不应未经处理直接发布：

```bash
git status --short
git diff --check
git ls-files
git ls-files -ci --exclude-standard
git check-ignore -v --no-index doc/report.pdf data/prompt_embeddings/example.pt output/example.txt .env
```

检查当前树与历史时，应关注文本身份字段与个人路径、私有链接、图片 EXIF/XMP、PDF 元数据、截图界面、访问凭据，以及历史中已删除的文件和提交作者信息。

## 本地保留与清理

被忽略不代表可以删除。模型权重、嵌入、原始实验结果和本地 PDF 具有保留价值，应与可再生缓存区别处理。

删除缓存前应列出实际存在的相对路径、空间、重建方式与影响，并在获得确认后仅删除已批准项目。不要将 `.git/` 作为缓存对象，也不要使用范围不明确的 `git clean -fdx`。
